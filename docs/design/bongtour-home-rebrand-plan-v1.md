# 봉투어 홈·브랜드 전면 방향 — 로컬 계획 v1

**상태:** `draft-local` · **P0+P1 진행중 (Ocean Warm 고정)** — 완벽 확정·승인 전 **커밋·배포 금지**.  
**근거:** 현행 `bongtour.com` 홈·`globals.css` 토큰·시즌 히어로 스택 + 인더월드형 상품 표면 학습 + **「구체·준비된 설명이 인상·신뢰에 유리하다」** 운영 피드백.  
**주의:** **무조건 긴 글이 좋은 것이 아니다.** 군더더기·형용사 나열·반복은 오히려 해를 준다.  
**연동:** `docs/design/bongtour-product-surface-v1.md` (상품 상세). 홈과 상세는 같은 브랜드 축을 쓰되 역할은 분리한다.

---

## 1. 현행 진단 (있는 그대로)

### 1.1 홈이 하는 일 (실제 섹션 순서)

1. 라벤더 그라데이션 셸 + (숨은) SEO H1  
2. **시즌 큐레이션 히어로** 캐러셀 (풀블리드에 가깝, 카피·CTA)  
3. **eSIM 코랄 스트립**  
4. 시즌 연결 상품 그리드  
5. eSIM 상품 섹션  
6. 추천 여행지 (페르소나)  
7. 항공+호텔  
8. 맞춤·기관 서비스  
9. 공공기관 신뢰  
10. 고객 후기  
11. 하단 sticky: 전화 / 카톡(노랑) / eSIM(코랄)

### 1.2 브랜드 색이 쪼개진 상태

| 축 | 토큰 | 문제 |
|----|------|------|
| 로고·상담 | gold `#f2c94c` | 따뜻함은 자산이나 CTA와 카톡 노랑이 경쟁 |
| UI·링크·CTA primary | blue `#2f8fc7` / `#58b7e8` | 존재하나 홈에서 주연이 아님 |
| 가격·달력 | teal `#0d9488` | 세 번째 “메인”처럼 보임 |
| 페이지 면 | lavender `#efedf8` | 여행 사진·골드와 톤 충돌, “패키지 OTA” 인상 약화 |
| eSIM | coral `#d85a30` | 매출 채널로 강함 → **홈 중반을 코랄이 가로챔** |
| 우리끼리 | rose | 또 다른 액센트 |

**결론:** 기능은 많지만 **한 브랜드의 한 화면**으로 안 읽힌다. 전체 디자인을 바꿔도 되는 전제라면, “섹션 추가”가 아니라 **색 축 축소 + 홈 구성 재정의 + 설명 밀도 상향**이 정답이다.

### 1.3 카피 밀도

- 히어로 시즌 문장은 비교적 서사적(강점).  
- 그 아래 섹션은 **짧은 헤드 + 카드 나열** 위주 → “준비된 여행사” 인상보다 “모아둔 목록” 인상.  
- 경쟁(인더월드류)이 강해 보이는 이유는 글자 수가 많아서가 아니라, **동선·포함·제외·조건을 구체적으로 적기 때문**이다.  
- 운영 피드백을 바르게 해석하면: **“길어서 좋다”가 아니라 “알짜가 있어서 좋다”.**  
  → 콘텐츠 SSOT는 **정보 밀도·구체성**이지, 분량 최대화가 아니다.

## 2. 제품 진실 (홈이 팔아야 하는 것)

홈의 한 문장:

> 봉투어는 **해외 패키지·자유여행을 고르고**, 필요할 때 **eSIM·상담·기관 맞춤**까지 이어 주는 여행 허브다.

우선순위 ( Persuade 모드 ):

1. **여행 상품을 믿고 고르게** (시즌·목적지·가격 신호)  
2. **상담/예약으로 연결**  
3. eSIM은 강한 2번 상품이나 **1번을 죽이지 않게** 배치  
4. 공공·기업·우리끼리는 신뢰·확장 레인 (홈 하단)

Simplyur 앱 브랜드는 홈에서 “simply your” 보조로만 — 메인 히어로 브랜드 시그널은 **Bong투어**.

## 3. 최선의 방향 (권고안) — 「Ocean Warm Editorial」

이름을 붙이면: **Ocean Warm Editorial**.

| 축 | 선택 | 이유 |
|----|------|------|
| 시각 세계 | 여행 사진이 주연, UI는 편집형(칩·번호 USP·긴 본문) | 인더월드에서 마음에 든 패턴을 **홈·상세 공통 언어**로 |
| 브랜드 컬러 | **블루 primary + 골드 secondary + 샌드 뉴트럴** | 로고 DNA(골드) 유지, 신뢰·여행(블루) 주연화, 라벤더 폐기 |
| 채널 색 | coral = **eSIM 전용**, kakao yellow = **카톡 버튼만** | 플랫폼/채널 색과 브랜드 색 분리 |
| 기능 색 | teal = 성공·달력 가용만 (가격은 ink 또는 brand) | 가격이 청록으로 “제3브랜드”처럼 보이던 것 제거 |
| 홈 구성 | 첫 뷰포트 = 브랜드 + 시즌 히어로 하나 + CTA | 대시보드형 허브 카드 과밀 금지 |
| 카피 | **구체 정보 밀도** (아래 §5). 무조건 길게 쓰지 않음 | 인상·신뢰의 본체 |

대안 검토 후 기각:

- **라벤더 유지·미세조정만** — 색 축이 그대로라 “다른 사이트” 인상 불가.  
- **코랄을 브랜드 primary로** — eSIM=여행 본체가 되어 패키지 신뢰와 충돌.  
- **네이비+골드 럭셔리만** — 기관·대중 패키지 접근성과 거리. B2B 섹션에만 부분 적용 가능.

### 4.2 적용 범위 (한 번에)

1. `app/globals.css` `:root` — 토큰 교체 + lavender 사용처를 sand/white로 매핑  
2. Tailwind `bt-*` 유틸이 토큰을 보면 홈·상세·서브페이지가 같이 움직임  
3. 로고 SVG/워드마크: 골드+블루 비율만 재가이드 (파일 교체는 시안 후)  
4. OG·시즌 배너 템플릿: 코랄/라벤더 남용 금지 가이드  

### 4.3 시안 게이트 (색 확정 조건)

로컬에서 **같은 홈 목업 3버전**만 비교:

- A: Ocean Warm (권고)  
- B: 현행 유지+정리(라벤더↓, 축만 정리)  
- C: Deep navy + gold (럭셔리 편향)

사람 판정 기준: (1) 시즌 사진 위에서 브랜드가 보이는가 (2) eSIM이 본체를 잡아먹나 (3) 상담 CTA가 카톡과 안 헷갈리나.

**운영자 한 줄 선택 전 커밋 금지.**

## 5. 설명 품질 (Copy Substance) — 추가 잠금 원칙

> **무조건 긴 게 아니다.**  
> 짧은 UI·짧은 카드는 유지한다. 늘려야 할 것은 글자 수가 아니라 **빠진 알짜 정보**다.  
> 고객이 좋게 느끼는 지점 = 구체성·준비성·리스크 고지. 빈 수사는 길어도 감점.

### 5.0 길이 vs 밀도

| 잘못된 목표 | 올바른 목표 |
|-------------|-------------|
| 경쟁사보다 문단을 길게 | 같은 질문에 **답이 있게** |
| 모든 섹션을 장문으로 | 표면마다 **필요 정보만** (카드=짧, 상세 핵심=구체) |
| “더 써 넣기” | 중복·형용사 삭제 후 **사실 한 줄**이 남는지 |

**테스트:** 그 문장을 지워도 고객 결정(갈지·믿을지·뭘 포함하는지)이 안 바뀌면 **쓰지 않는다.**

### 5.1 어디에 무엇을 쓸 것인가

| 표면 | 분량 | 내용 |
|------|------|------|
| 홈 히어로 | 짧~중: 헤드 1 + 서포트 1–2문장 | 감성 + 왜 지금인지 (군더더기 금지) |
| 홈 섹션 리드 | **필요할 때만** 1–3문장 | 약속·차이가 **사실**로 있을 때만. 없으면 헤드+카드만 |
| 상품 카드 | 짧: 짧은 제목 + 보조 0–1줄 | 스캔용 |
| 상품 상세 | 핵심은 **구체 블록** (USP·포함·불포함·고지) | 길이보다 체크리스트 완결. 빈 문단 금지 |
| eSIM 스트립 | 짧+명확 | 설치·요금 한 호흡 |

### 5.2 품질 규칙 (분량 규칙이 아님)

1. **숫자·고유명·동선·조건**이 들어가거나, 문장을 쓰지 않는다.  
2. **형용사 나열 금지** (엄선·프리미엄…) — 기존 제목 금칙과 정합.  
3. **리스크·불포함**은 숨기지 않되, 한 번만 정확히.  
4. 모바일에선 접기 가능 — 다만 접기 안에 **또 물타기** 금지.  
5. 공급사 원문 복붙·장황 재서술 금지 — 봉투어 톤으로 **압축 재서술**.

### 5.3 홈 섹션별 카피 슬롯 (초안 스펙)

각 섹션:

- `eyebrow` (선택)  
- `headline` (1줄)  
- `body` (선택, **사실 있을 때만**; 권장 상한 ~200자, 하한 없음 — 빈약하면 생략)  
- `ctaLabel` + href  

예: 「시즌 연결 상품」  
- 목표: *가격·출발 갱신 방식*처럼 **모르는 사람 질문에 답하는 1–2문장**. 없으면 제목만.

예: 「항공+호텔」  
- 목표: FIT vs 패키지 차이 **한 번에 이해되는** 2문장 이내.

### 5.4 콘텐츠 생산 파이프라인 (나중에 구현)

- 시즌 히어로: 기존 큐레이션 CMS 유지, **서포트 문장 최소 길이 가드** 추가 검토.  
- 상품 상세 USP/포함: highlight·includedText 정제 렌더러 (product-surface v1).  
- 홈 섹션 body: 초기에는 코드/로컬 JSON 카피 SSOT → 이후 admin 필드.

## 6. 홈 정보구조 재설계 (전체 디자인이 바뀌어도 됨)

### 6.1 첫 뷰포트 (하나의 구성)

허용 요소만:

- 브랜드 (로고 히어로급 시인성)  
- 시즌 히어로 비주얼 (풀블리드)  
- 헤드 + 서포트 1–2문장  
- CTA 그룹 1개 (시즌 떠나기 / 상담)  
- 페이지네이션 점  

금지: 첫 화면에 통계·파트너 로고 줄·eSIM 코랄 블록·허브 카드 그리드.

### 6.2 스크롤 이후 (한 섹션 = 한 일)

권고 순서:

1. **어디로 갈지** — 목적지/메가 진입 (짧은 탐색 + 선택적 긴 안내 문단)  
2. **이달의 상품** — 그리드 + **섹션 body 중장문**  
3. **왜 봉투어인가** — USP 번호 4–6개 (상세와 같은 언어, 홈용 요약판)  
4. **eSIM** — 코랄 레인 단독, 여행 본문과 시각 분리  
5. **자유여행(항공+호텔)** — body 중장문 + 카드  
6. **신뢰** — 공공·후기 (과장 없이 증거)  
7. **기관·우리끼리** — 하단  

현행 Persona + AirHotel + Service + Trust + Reviews는 **통합·삭제·순서 변경** 후보. 기능 삭제가 아니라 **한 일 원칙으로 재배치**.

### 6.3 연락·푸터 (디바이스 분리)

| 표면 | 행동 |
|------|------|
| **모바일** | 하단 sticky: 상담 · 카톡 · 전화 (eSIM sticky 제외). 그 아래/스크롤 끝 **사이트 푸터** |
| **PC** | sticky 삼분할(상담/카톡/전화) **쓰지 않음**. 상단·히어로 CTA + **푸터**에 전화·카톡·상담·사업자 정보 |

PC에서 모바일 sticky를 그대로 두면 “휴대폰 웹앱”처럼 보인다.

## 8. 실행 로드맵 (로컬 → 승인 →만 배포)

| Phase | 산출 | 커밋 |
|-------|------|------|
| **P0** | 본 문서 + product-surface v1 + (미작성) tokens/SSOT 초안 | ❌ |
| **P1** | 홈·상세 **정적 목업** (HTML/라우트 `/dev/...` 가드 또는 Figma) A/B/C 색 | ❌ |
| **P2** | 카피 SSOT: 홈 섹션 body 초안 전체 + 상품 상세 샘플 5개 장문 | ❌ |
| **P3** | 운영자 색·구성·카피 밀도 승인 | — |
| **P4** | tokens → `globals.css` / 홈 리팩터 / 상세 플래그 | 승인 후 |
| **P5** | Pretendard·칩·sticky·eSIM 격리 QA | 승인 후 |

**완벽의 정의 (홈+브랜드):**

- [ ] 색 A안 시안이 로고·시즌 사진·eSIM과 동시에 안정  
- [ ] 첫 뷰포트가 대시보드가 아님  
- [ ] 홈·상세에서 **알짜 빠진 곳**이 메워졌는지 (분량 자랑 아님)  
- [ ] 상세 샘플에서 “뭐가 포함인지 모르겠다” 피드백이 재발하지 않음  
- [ ] 플래그 OFF 시 현행과 동일  
- [ ] Explicit “커밋·배포 허용”
